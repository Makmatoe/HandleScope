# HandleScope 0.1.4

This compatibility-contract release authorizes a narrowly bounded,
user-confirmed SessionDock setup path. HandleScope's runtime behavior and
compiled Roblox automation policy are unchanged.

## Confirmed managed setup

- A compatible SessionDock release may install this separately released
  HandleScope package only after a dedicated confirmation names the exact
  version and discloses immediate API startup and limited per-user autostart.
- SessionDock must pin the immutable canonical Windows x64 package and checksum
  assets, including their exact lengths and SHA-256 hashes. It must reject any
  other repository, version, asset, checksum, redirect, archive layout, or
  internal file inventory.
- The release's unmodified installer must pass `-VerifyOnly` before the
  installation phase. Both phases run as the current standard user.
- A verified child process may use process-scoped `RemoteSigned`; `Bypass`,
  `Unrestricted`, saved policy changes, Group Policy overrides, and elevation
  remain forbidden.
- The managed install may pass `-StartNow -EnableAutostart` only as disclosed by
  the confirmation. Enabling SessionDock's use of the API remains a separate
  explicit action.

## Unchanged safety boundary

- HandleScope is not bundled into SessionDock and has no updater or telemetry.
- SessionDock may not silently download, install, retry, update, start, stop,
  uninstall, or reconfigure HandleScope.
- The local API still accepts only the compiled
  `roblox-singleton-event-v1` policy and still refuses elevated, service-account,
  and session-0 execution.

## Validation

The release passes the full Windows build, Windows PowerShell 5.1 compatibility
suite, controlled native-handle and strict API tests, dependency and repository
gates, and the isolated publish, finalization, and asset-verification pipeline.
