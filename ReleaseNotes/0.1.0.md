# HandleScope 0.1.0

This is the first public HandleScope release for Windows x64.

## Included

- A portable desktop tool for reviewing and closing named handles in
  non-elevated, same-user, same-session processes.
- A separately installed local API restricted to the exact Roblox singleton
  event policy used by SessionDock.
- Per-user PowerShell install, start, stop, client, and uninstall scripts.
- An explicit helper that enables SessionDock's local HandleScope setting
  without copying tokens, launching software, or touching account data.
- A self-contained release ZIP, SHA-256 checksums, an SPDX SBOM, release notes,
  and GitHub build provenance.

## Security changes

- The desktop and API run as the current standard user (`asInvoker`), never
  enable `SeDebugPrivilege`, and do not request UAC approval.
- The API refuses elevated, service-account, and session-0 execution and allows
  only one instance per Windows user session.
- Protected endpoints use a rotating 256-bit bearer token over IPv4 loopback.
- The compiled API policy accepts only a verified, same-user, same-session,
  non-elevated `RobloxPlayerBeta.exe` and the exact
  `ROBLOX_singletonEvent` event, type, and access mask.
- Every close requires a successful dry run followed by an identical,
  single-use request within five seconds. Process and handle identity are
  revalidated before closure.
- The optional sign-in task is per-user and limited privilege. Autostart is off
  by default.

## Privacy and delivery

- HandleScope has no telemetry, advertising, analytics, crash upload, account,
  cloud service, or automatic updater.
- API runtime data stays under `%LOCALAPPDATA%\HandleScope`; the bearer token is
  not written to logs.
- The API installs under `%LOCALAPPDATA%\Programs\HandleScope\Api` and can be
  removed with its included uninstaller.
- Releases use no paid certificate or signing service and are intentionally not
  Authenticode-signed. Verify the repository-bound GitHub attestation, release
  ZIP checksum, internal manifest, and SPDX SBOM before use. Windows may report
  **Unknown publisher**.

## Known limitations

Closing a handle can terminate or destabilize an application. Keep unsaved work
closed and use HandleScope only on processes you own and can safely restart.
Elevated, protected, cross-user, and cross-session targets are intentionally
unavailable. Other programs running as the same Windows user are not isolated
from the local API token; the compiled policy limits what that token can do.

Compressed self-contained builds may extract .NET native runtime components
beneath `%TEMP%\.net` when launched. HandleScope otherwise operates locally and
does not contact an update or telemetry service.
