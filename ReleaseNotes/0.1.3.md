# HandleScope 0.1.3

This security-hardening release closes the process, handle, API lifecycle, and
release-verification gaps found during a complete repository audit.

## Safer process and handle operations

- Desktop process rows now keep the exact creation identity that supplied their
  displayed name, preventing PID reuse from pairing an old label with a new
  process.
- Desktop and API handle scans are pinned to that process instance and reject
  identity changes before returning actionable results.
- Handle snapshots are revalidated against a fresh system table, including the
  object address, access mask, type, attributes, and trace metadata.
- Closing a handle now rejects changed access rights as well as recycled object
  identities before requesting `DUPLICATE_CLOSE_SOURCE`.

## Stronger local API contract

- Every successful dry run receives an independent random 256-bit `planId`.
  Execution must present that ID with the identical selector within five
  monotonic seconds, and each plan is consumed once.
- Unauthorized lookalike processes no longer consume the 32-process authorized
  target cap.
- The strict reader accepts only the exact `application/json` media type and
  rejects lookalikes such as `application/jsonp`.
- Multi-process execution responses no longer truncate reviewed matches.
- The bundled PowerShell client and documented SessionDock contract use the new
  plan-ID binding.

## Reliable lifecycle behavior

- Startup preserves discovery data and blocks when an existing API process is
  live or cannot be inspected safely.
- A definitively stale connection is replaced only after a new API instance
  successfully publishes its own discovery document.
- Installation now reports the observed enabled, disabled, or absent autostart
  state instead of claiming it is disabled when an enabled task was preserved.

## Release and supply-chain hardening

- Draft release assets are compared byte for byte with trusted workflow
  artifacts before semantic verification.
- Release-asset verification treats extracted files strictly as data and never
  invokes an extracted installer or executable.
- Finalization rejects equal, nested, ancestor, and filesystem-link-aliased
  input/output paths before any recursive cleanup.
- Dependency gates inspect repository MSBuild inputs, evaluated Debug and
  Release `PackageReference` items, and generated NuGet restore graphs.
- Download verification instructions derive the version from the selected asset
  instead of carrying a stale hard-coded release number.

## Validation

The release passes the full Windows build, Windows PowerShell 5.1 compatibility
suite, controlled native handle tests, strict API tests, production Windows
signature-rejection checks, dependency and repository gates, real junction
path regression, and an isolated publish/finalize/asset-verification pipeline.
